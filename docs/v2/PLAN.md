# v2 MVP 实施计划

基线：`fdab778b6b51181bd76c3627b765da8af5ed6eef`；分支 `codex/v2-mvp`。
保留原生 SwiftUI/SwiftData、英文 UI、现有部署目标和签名。TSS 是旧指标；新 Cardio Load 和分运动区域代理量独立。无恢复预测、百分比、医学结论、服务器或发布。

## 里程碑与验收

1. A1 时间与缺失：时间区间积分、30 秒 NP、暂停/长缺口/乱序/异常/重复样本，规则与不规则采样一致性测试。
2. A2 导入：FTP 解耦，关联 HK quantity series，受限 fallback、踏频/力量分类、来源和质量；离线/无可读数据不删除历史。
3. A3 同步：幂等更新、多源单次贡献、删除重算；先导入再补组再同步、先手动后关联均保留用户记录。
4. B1 体感：前后人体图和可访问列表，左右独立，跳过/无不适/未知，新增编辑删除补录历史与重启持久化。
5. C1 力量：26 个动作、搜索区域过滤、模板、组次重量努力可选，RIR=0；已有会话补充/新建/后关联。
6. D1 区域模型：跑骑游力量可解释粗等级，使用真实分布/踏频/坡度/泳姿/器械输入，版本、覆盖、原因、个人近期背景，无假左右差异。
7. E1 用户流程：Today 心肺/区域/快速体感，区域贡献与反馈历史，活动标签重算，旧 TSS/CTL/ATL 入口，首次/空/离线可用。
8. F1 研究边界：观测与录入时间、输入截止、历史估计与原依据保留，不做恢复学习。
9. M1 迁移：旧 Workout/设置/聚合保留，新增可选或默认字段，手动信息与重算独立；真实旧库升级验证。
10. V1 回归：纯 Swift 行为测试、原测试、iOS 编译/迁移/模拟器用户路径、独立审查和修复。无法运行明确 blocked。

顺序：时间领域与持久化完整切片 → 导入与去重 → 交互与派生结果 → 行为回归与独立审查。每轮在 STATUS 记录可观察行为、风险、检查与结果。最终提交并尽可能推送 draft PR；不调用带 TestFlight 后操作的现有 Xcode Cloud。
